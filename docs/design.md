# コードリーディングの設計

学習者は、1つのソースを暗いエディタに貼り付け、範囲を選び、その範囲の説明を書く。判定が返ると、コードの横に薄い文字で「合っている」「抜けている」「誤解」とフィードバックが乗る。入力欄は選択範囲の上だけに出る。

次にこのコードを持つ人は、書き込み口が `StudySession` の遷移関数だけだと分かる。4つの表示はセッションから自分の読み取りモデルを作る。

型の正本は `domain/` にある。この文書は、なぜその形かと、データの流れを書く。

## 4つの責務

コード表示は `domain/code-display.ts` が持つ。正本は `SourceDocument` の文字列である。`toCodeView` が行番号と offset を導出する。説明文も判定も持たない。

範囲選択は `domain/range-selection.ts` が持つ。正本は `CodeRange` の文書 id と、文字列上の開始 offset と終了 offset である。`selectRange` だけがこれを作る。説明文は持たない。

説明入力は `domain/explanation-input.ts` が持つ。編集中の文字列は `DraftState` の `editing` にある。提出後の本文は空でない `Explanation` である。モデルは呼ばない。

判定結果表示は `domain/judgment-display.ts` が持つ。`Judgment` は `verdict` と空でない `feedback` である。`verdict` は `aligned`、`missing`、`misunderstood` のいずれか1つである。`toInlineNotes` が範囲つきの注釈を作り、文言は「合っている」「抜けている」「誤解」になる。注釈は範囲全体に付く。開始行だけには寄せない。重なる範囲では、同じ行に複数の注釈が乗ってよい。モデルは呼ばない。

## セッション

`domain/session.ts` の `StudySession` が4つをつなぐ。`empty` か `active` のどちらかである。`active` はソース、`draft`、判定済みの `entries` を持つ。`draft` は `idle`、`editing`、`submitting` のいずれかである。

遷移関数は値を返すだけで、通信はしない。

`pasteSource` は `empty` からだけ `active` にする。別のファイルを貼るには `resetSession` で `empty` に戻す。戻した `empty` を `save` すると、ファイル上の判定も消える。

`beginSelection` は `idle` または `editing` から `editing` にする。同時に編集できる説明は1つである。`submitting` のあいだは次の選択を始めない。範囲が違えば、注釈は両方残る。同じ開始 offset と同じ終了 offset に、文を変えてもう一度提出すると、その範囲の前の注釈は新しい判定に置き換わる。

`markSubmitting` が説明を確定し、`toJudgeRequest` がソース、範囲、抜粋、説明をまとめる。ページが `JudgePort` を呼ぶ。成功すれば `applyJudgment` が entry を足して `idle` に戻す。失敗すれば `restoreEditing` が編集中に戻す。

`ExplanationId` は文書 id、開始 offset、終了 offset、説明本文から決まる。同じ提出をもう一度適用しても `entries` は増えない。同じ範囲で本文だけが違う提出は、その範囲の entry を置き換える。

## モデルの境界

`domain/judge-port.ts` の `parseJudgment` が未知の JSON を `Judgment` に変える。フィードバックが空なら失敗する。エラーは `kind` だけを持つ。表示用の英文は持たない。ビューが import するのは `Judgment` までである。

判定を出すモデルは `claude-haiku-4-5-20251001` である。貼り付けるのは練習用のコードで、判定のためにこの API へ送る。モデル名と API キーは Route Handler の中だけに置く。2026-09-22 に Anthropic のモデル一覧を見ると、このモデルは速く、性能は上位に近い、と書いてある。料金は入力 100万トークンあたり $1、出力は $5 である。ソースが約 3000 トークンで、フィードバックが約 200 トークンのとき、この料金で 1 回およそ $0.004 になる。これは公開料金からの計算で、API を叩いた実測ではない。

より安い `gpt-5.6-luna` は、OpenAI のモデルページで以前の nano 相当とされている。入力は 100万トークンあたり $0.20、出力は $1.20 である。取り違えを見逃すと、学習者は誤った読みのまま次へ進む。最初のモデルにはしない。

`gpt-5.6-terra` は入力 $2、出力 $12 である。同じ短い出力でも Haiku より高い。Gemini の Flash は、思考に使ったトークンも出力料金に入る。注釈が短くても料金が読みにくいので、使わない。

`aligned` は、選んだ範囲の主目的を、事実と違う主張なしに言えているときである。主目的でない言い落としは `aligned` のままにする。

`missing` は、書いてあることが範囲と矛盾せず、主目的の一部か、結果に効く条件を言っていないときである。

`misunderstood` は、範囲の動き、値、または呼び出しについて、事実と違うことを書いているときである。事実と違う一文があれば、ほかが合っていても `misunderstood` である。

`feedback` は日本語で1文か2文である。どの読みが合っていたか、何が抜けていたか、どこが事実と違うかだけを書く。コードの書き方の良し悪しは書かない。範囲に無い関数や API は足さない。

## 画面

`StudyPage` がセッションを1回だけ分岐する。`CodeView`、`SelectionLayer`、`ExplanationComposer`、`JudgmentLane` はその結果だけを描く。入力欄は `editing` のときだけ、選択範囲の上に出る。

ページは `/` だけである。地は `#f3a04a`。その中に角の丸い窓が1つあり、窓の色は `#2a1c14` である。左上の灰色の点は3つで、飾りである。窓の操作にはしない。コードは `#f0e2c4`。コメントは `#8d7d6e`。色は Tailwind のトークンで指定する。行番号の欄は出さない。offset は `CodeLine` が持ったままである。

キーワード、文字列、JSX の名前、コメントは、同じ文字列上の span で塗る。行の分割は `toCodeView` が行う。

説明欄は `textarea` と `button` である。位置だけ Floating UI で、選択範囲の上に出す。UI キットは入れない。Monaco も CodeMirror も置かない。どちらも文書と選択を自分で持つので、offset の正本が二つになる。

これらの部品はまだ置いていない。

## 枠

フレームワークは入っている Next.js 16 の App Router のままである。サーバが持つのは判定の Route Handler だけである。セッションの HTTP は作らない。Vite には張り替えない。判定の受け口は残るし、殻を捨てても学習者の操作は変わらない。

## 保存

永続化の単位は `StudySession` のスナップショット1つである。置き場はブラウザの OPFS 上のファイル1つである。SQLite も Postgres も置かない。開く操作は文書1つで、検索はしない。

公開面は `SessionVault` の `open` と `save` である。ディスクに載るのは `empty` か、`idle` または `editing` の `active` だけである。`submitting` はメモリにだけ置く。保存の前に `restoreEditing` した値を書く。同じ値の再保存はファイルの置換である。`applyJudgment` が同じ提出を二度受けても `entries` は増えない。書き込みの途中で落ちたら、前のファイルが残る。

`SourceDocument.id` は復元時に作り直さない。`pasteSource` は新しい id を出すので、vault は保存済みの id をそのまま戻す。

アカウントは作らない。別のブラウザではセッションは見えない。OPFS を消すとセッションも消える。OPFS が使えないときは、そのタブのメモリだけで続け、`save` は `unavailable` を返す。壊れたファイルと、知らない版のファイルは `corrupt` である。空のセッションに黙って戻さない。

タブを2つ開いたときは、後から書いた方が残る。マージはしない。判定中にリロードすると、ディスク上は `editing` である。自動では再提出しない。

## 捨てた形

段階ごとにソースと判定一覧を持つ5つのセッション型は取らなかった。同じフィールドの繰り返しで、読む量が増える。

行と列を保存する範囲は取らなかった。表示と選択で位置の表現が二つになる。

注釈を開始行だけに置く形は取らなかった。複数行の選択で、フィードバックの位置が範囲とずれる。

文言のない判定は取らなかった。学習者へ返すフィードバックが型に無い。

提出関数がポートを待つ形は取らなかった。セッションの確認に通信が必要になる。

エラーに英語の message を持たせる形は取らなかった。日本語の文言がドメインに漏れる。

## 今回やらないこと

音声入力、複数ファイル、アカウントはやらない。サーバにセッションの行は置かない。

## 確認

`scripts/trace-session.ts` が、空の貼り付け、逆順の選択、空の説明、判定の追加、同じ提出の再適用、同じ範囲の置き換え、空のフィードバック、ポートの失敗を順に通す。実行は `npx tsx scripts/trace-session.ts` である。
